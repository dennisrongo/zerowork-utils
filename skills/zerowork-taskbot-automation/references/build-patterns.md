# Verified build patterns (each one ran end-to-end on real bots)

## Data attachment: the per-bot rule

Tables are per-TaskBot instances. `zw.setRef` to an unattached table fails: *"The table
with ID NNN does not exist in this TaskBot"* even though the table exists in the account.
Attachment happens at creation (`connector_id`). No route attaches an existing table to
another bot (405) — always create fresh per bot. Every bot auto-gets a "Variables" table
(`is_autogenerated: true`).

- Create + attach + columns in one REST call:
  `POST /data_group/` `{name, type: 'NATIVE', columns: [{colName}...], connector_id: <botId>}`
- Add a variable = `POST /data_group/<varsTableId>/column/` `{name: 'price_raw'}` (field
  is `name`, NOT `colName`, on existing tables).
- Runtime API (Write JS): `zw.setRef({ref_id, name, value, appendIndex})` /
  `zw.getRef({ref_id, name})`. Value must be a string; `appendIndex` = 0-based row for
  table writes (works WITHOUT any loop — verified 20/20 rows). Writing to a missing
  variable errors the run. zw surface also: browserContext, delay, deviceStorage,
  getAgentInfo, getTaskBotInfo.
- Variables are runtime refs, NOT rows: item APIs on the Variables table return 0 even
  after successful writes. Verify via Log interpolation.
- Reading table rows inside a bot = Dynamic Loop (Start Repeat → Dynamic) over the table ref.

## Pattern 1 — native list scrape, no JS (verified 20/20)

```
Start Repeat (Standard → Count elements matching selector, lead `.product_pod h3 a`)
  → Save Web Element × N (inside loop)
```
- Incremental selector = **XPath with positional predicate**:
  `(//article[contains(@class,"product_pod")])[{loop_index}]//h3/a`
- CSS `:nth-of-type({loop_index})` BREAKS when matches live under different parents
  (grid rows) — found element 1 then hard-failed. XPath indexes the global match list.
- Without `{loop_index}`, SaveWE grabs the FIRST match every iteration (20 identical rows).
- Save Web Element → Save-as: **Custom attribute** + attribute name (`title`) for attr
  scraping; Text/Link/HTML/Image URL for the others.
- "Skip if no element is found" toggle makes missing elements non-fatal.

## Pattern 2 — pagination via nested loops (verified 54/60 rows, 3 pages, 11s)

```
Open Link
→ Start Repeat (outer, Standard → Fixed N = page count)
→ Start Repeat (inner, Standard → Count elements + lead selector)
     inner out 1 → SaveWE × N (XPath {loop_index} per column)
     inner out 2 → After Repeat → Click (Next `li.next > a`) → Log
```
- **After Repeat takes the INNER loop's SECOND output** — never chain it after the saves
  (validator: "must be preceded by a single Start Repeat").
- Race: last-page saves can beat render (~6/60 missed). Mitigate with a Delay after
  Click Next or a wait-selector check.
- Start Repeat MAY have multiple outgoing edges; all other blocks single-out only.

## Pattern 3 — Write JS scrape with table writes (verified 20/20)

Open Link → Write JS (scrape via document.querySelectorAll, then per-row
`zw.setRef({ref_id: <dgId>, name: 'title', value, appendIndex: i})`) → Log.
No loop blocks needed at all. Monaco editor: set code via
`monaco.editor.getEditors()[0].getModel().setValue(code)`.

## Pattern 4 — advanced logic pipeline (verified)

Open → Try → [click(.nonexistent) → caught] → After-Try → Log → Update Data (`£51.77` →
var) → Regex Replace `/£/` → '' → var → Start Condition (price_clean) → Set Condition
(> 50) → Log HIGH / Else Set Condition → Log LOW.

Wiring rules: catch AND after_try hook directly off the try node. Numeric comparisons
throw on non-numeric strings — sanitize first. Full wiring rules: rest-api.md.

## Pattern 5 — browserless data pipeline (verified, ~1-5s runs)

Send HTTP (GET api) → math (op on value) → Ask ChatGPT (prompt referencing the var,
answer → var) → Log (interpolates both). No browser launch: run completes in ~1s; with
ChatGPT ~5s. Duration is the signature that blocks actually executed.
